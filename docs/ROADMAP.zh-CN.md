# 后续开发路线与持续复用检索

[English](ROADMAP.md) | **简体中文**

## 0.1 — 验证本地个人应用闭环

应用库、API 生成和编辑、点选字段定位、离线表单/统计、独立记录与版本、本地观察与低风险自动修改。无需自建业务服务器。

当前运行时的范围是记录/表单/统计；自主优化以两个本地规则开始。完整自由布局、更多任务类型和自主提出复杂功能仍属于后续工作，不把它们写成已完成能力。

## 0.2 — 原生编辑工作区（已实现）

已实现点选、底部面板、本地属性、持续草稿、撤销重做、连续对话、范围与迟到检查、隔离试用、冲突合并、分组 / 隐藏、固定动作、受限数据转换。详细范围与设备验收缺口见 APP_EDITING_INTERACTION.md、VALIDATION.md。

## 0.3 — 扩展可组合组件

优先评估 DivKit 的本地 JSON 渲染是否值得替换目前的小型运行时，并对比原生 RecyclerView/Compose、schema 校验库的体积、冷启动、维护与许可。先做可选字段/分组/筛选/图表，再考虑计时器、日历、通知。每类新组件的执行能力须可显式描述、测试、迁移。

验收：不调用 LLM 也可完成常见布局和字段调整；兼容已有 AppSpec v1；普通使用持续离线可用。

## 0.4 — 更可靠的个人适应

继续参考 Möbius 的问题记录与建议机制，以及自适应 UI 研究；补充本地任务级事件、可解释建议、按用户指定目标评估、置信度与撤销后冷却。LLM 仅在本地规则不足时接收最小化摘要，并有用户设置的预算和触发范围。

验收：预注册一项任务指标，比较修改前后表现；区分少用与难找；稳定主要入口；拒绝使用“停留更久”代替“更有效”。

## 0.5 — 本地能力与应用协作

逐项检索离线 OCR、搜索、文件导入、图表等开源实现，先核实许可证再集成；不预先承诺某项目已适用。跨应用读取必须有明确能力授权与数据归属，不能因为共用宿主就默认共享全部记录。

## 服务器引入门槛

只有跨设备加密同步、多人共享、集中计费、企业策略等需求出现时，再设计可选服务端。运行、统计、版本恢复不因此转移到后台。LLM 仍由 API 提供，不部署本地大模型。

## 每个阶段都重复的工作

1. 针对具体模块检索当前开源项目及官方文档。
2. 记录版本、许可、近况和真实可运行性，区分宣传、原型与实现。
3. 做最小集成验证，比较本地执行、耗电、包体与引入的服务器依赖。
4. 更新 OPEN_SOURCE_REVIEW.md、计算部署表和测试报告。
