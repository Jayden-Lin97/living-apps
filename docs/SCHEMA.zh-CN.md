# AppSpec v1 / v2

[English](SCHEMA.md) | **简体中文**

可运行样例见 `app/src/test/resources/live-generated.json` 和 `live-edited.json`，为不含业务记录或凭据的脱敏离线回归样例。

## 子应用描述

| 属性 | 含义 |
|---|---|
| schemaVersion | 数值 1 或 2；保留 v1 应用兼容，只有 v2 允许下列扩展 |
| name / description / icon / accent | 名称、说明、符号、六位十六进制颜色 |
| fields | 1–20 个稳定字段，按显示顺序排列 |
| titleField | 列表标题使用的字段 ID |
| metricField / unit | 可选数字统计字段与单位 |
| startScreen | overview / records / stats |
| quickAdd / compact | 快速入口与紧凑记录布局 |

字段包括 `id,label,type,required`，可选 `placeholder,options,defaultValue`。类型为 text、number、boolean、date、choice。choice 有 1–30 个选项；日期为真实 ISO 日期；数字必须有限。

描述不是程序，未知属性会被拒绝。没有网络请求、脚本、SQL、文件路径、外部插件或凭据字段。LLM 输出只有通过本地解析和兼容检查后才能采用。

## 版本与数据

应用表只保存当前版本指针。版本表保留描述、来源、原因与时间。记录表用独立应用 ID 关联原始 JSON 值。

更新保留所有旧字段 ID、类型和选项。新增必填项必须有默认值；默认值在缺少该字段的旧记录上读取生效，不强行重写原始记录。显式空值与缺失字段不同，不以默认值覆盖用户主动清空的可选项。

保存记录时校验提交表单所对应的版本；版本已经变化则要求重新打开。切回旧 UI 后编辑记录，只更新该 UI 可见字段，保留它没有显示的新字段。

恢复是创建一个新版本，不删除旧版本或记录。备份导入为新副本，其结构错误会使整个事务回滚。

## v2 的能力扩展

字段新增可选 `group`（最多 40 字）与 `hidden`（严格布尔值，默认 false）。隐藏只影响表单和记录卡片显示，保留业务值、稳定 ID 和显式统计引用。标题字段不可隐藏；隐藏必填字段必须有合法默认值，提交前还检查既有记录。组名依字段顺序形成分段，不形成任意坐标布局。

根对象新增 `actions` 数组，最多 6 个。仅支持以下结构：

```json
{"id":"water","label":"记一杯水","kind":"add_record","values":{"volume":300,"date":"$today"}}
```

ID 与字段 ID 使用相同格式且动作间唯一，名称 1–30 字。values 只引用已有字段；值符合字段类型，遗漏项使用默认值或空值，完整预设必须通过记录校验。只有 date 预设接受 `$today`，表示点击当天。运行时仅在用户点击后新增一条本机记录；试用时只写临时库。没有脚本、通用表达式、网络或自动触发能力。

## 草稿与转换

每应用一个活动草稿，保留正式基线、语义修订号、独立存储修订号、30 步历史、输入、对象、相关对话和最多 100 条 / 1 MB 临时记录。API 上下文不包含 controls、业务记录或试用数据。保存草稿使用存储修订号比较并交换；语义修订号用于识别模型迟到结果。

普通修改继续禁止改变已发布字段类型或移除旧选项。专用 MigrationPlan 才可转换：text ↔ number/date/boolean、累计数字项乘以显式正倍率并改单位、完整 choice 映射。默认值和固定动作预设同步转换；不自动猜测单位、填补空值或部分提交。含“点击当天”日期动作的类型转换须先处理该动作。

转换前检查正式基线、无脏草稿、现有记录指纹与失败数；备份写入并回读 SHA-256 校验后，记录、新版本和 data_epoch 在一个事务内提交。转换暂限每应用 5000 条 / 5 MB 备份；不上传数据。旧 UI 不能跨 data_epoch 恢复；转换前备份经校验后恢复为独立应用副本，保留当前应用与新记录。备份保存在应用私有 SQLite；没有宣称数据库文件加密，API Key 仍另由 Keystore 保护。
